IMPLEMENTATION UNDER TEST
-------------------------

1. Agent mode now uses Agent.stream_async() and forwards its user-facing stream
   events, matching the pre-graph response behavior.

2. Graph mode now uses Graph.stream_async(), suppresses router/resolver/evidence
   node streams, and forwards only events from the synthesis node. Users should
   therefore see one polished final response instead of internal graph output.

3. The graph synthesis prompt now explicitly requires polished natural prose,
   direct answers, concise organization, important caveats, safe adherence to a
   requested tone, and no exposure of internal evidence or graph terminology.

INTERPRETATION
--------------

The completed historical comparison suggests that the specialized graph can use
fewer total tokens because each node receives a narrower prompt and tool set.
However, it is much slower because its router, resolver, retrieval, and synthesis
model calls execute sequentially. It also produces substantially more output
tokens through intermediate agent reports and final synthesis.

The single-agent workflow is considerably faster for this simple single-park
question. The graph's main benefit is deterministic routing and separation of
responsibilities, not latency. Neither workflow is inherently always cheaper:
retrieval-result size, repeated tool cycles, and whether the model batches tool
calls can outweigh the architectural difference.


RECOMMENDED CLEAN RERUN
-----------------------

After the Gemini quota resets, run the same single-park prompt once per mode with

GraphResult and measure:

For a reliable conclusion, run each mode at least five times and compare median

whether tool calls are issued sequentially or in parallel.
